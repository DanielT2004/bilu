# Recommendation capacity result — 2026-09-14 stress

Environment: deployed Supabase Edge Function `recommendations` version 17,
Gemini `gemini-3.6-flash`, standard paid tier. The test used 50 isolated,
short-lived test users and synthetic Los Angeles-area prompts. Each user made
exactly four searches. All 50 accounts were deleted after the run.

## Test setup

Supabase's password-session preparation limit was reached before the first
attempt could send application traffic. That preparation attempt made no Gemini
calls and deleted all 38 accounts it had created. For the completed run, the
relevant Auth preparation limits were raised temporarily, 50 sessions were
created, and the original limits were restored before k6 sent any traffic.
This kept the production Auth configuration unchanged during the measured run.

## Scope

This proves the deployed recommendation path through a 50-user burst for the
tested request mix: four searches per user and 200 searches total. It does not
prove sustained traffic, concurrency above 50, or a different geographic/query
mix. No Gemini quota or spending-cap exhaustion occurred, so the provider
circuit breaker was not deliberately triggered.
